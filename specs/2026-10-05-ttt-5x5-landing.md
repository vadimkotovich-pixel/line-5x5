# Spec — «Линия 5×5» (2026-10-05)

## Problem

Нужен мини-лэндинг, который сам по себе является игрой: посетитель попадает на страницу и сразу может
сыграть партию против компьютера. Обычные крестики-нолики 3×3 слишком быстры и всегда ничейны — поэтому
поле 5×5, порог «три подряд», подсчет очков и блокировка зачеркнутых клеток.

## Goal

Одна статическая страница `index.html`, открываемая двойным щелчком (без сервера и сборки), где:
на первом экране играбельное поле 5×5; игрок играет `X` против компьютера `O`; за каждую собранную
тройку начисляются очки; зачеркнутые клетки блокируются навсегда; побеждает тот, у кого очков больше.

## Scope (входит)

- Поле 5×5, ходы строго по очереди (очко **не** дает дополнительного хода).
- Тройка = 3 подряд в одной линии (горизонталь, вертикаль, обе диагонали).
- Линия длиной `L ≥ 3` дает `L − 2` очка (4 в ряд = 2, 5 в ряд = 3).
- Все клетки засчитанной линии блокируются навсегда: занять их больше нельзя.
- Партия кончается, когда нет свободных клеток **или** когда оставшиеся свободные клетки не могут дать
  ни одной тройки ни одному игроку.
- Компьютер: уровень «средний» — берет свое очко, блокирует чужое, иначе играет по позиционной оценке;
  никогда не отдает больше, чем берет.
- Лэндинг вокруг игры: шапка с навигацией, hero с игрой, блок правил с мини-схемами, таблица очков,
  блок «как обыграть компьютер», футер. Адаптив от 320 px, тёмная тема.
- Доступность: управление с клавиатуры (стрелки + Enter/Space), `aria-live` для статуса, видимый фокус,
  поддержка `prefers-reduced-motion`.
- Тесты на `node --test` без зависимостей: правила, бот, контракт UI↔HTML.

## Non-Goals (не входит)

- Сервер, мультиплеер, аккаунты, сохранение партий между сессиями.
- Сборка (Vite/Webpack), фреймворки, npm-зависимости.
- Полный игровой поиск (минимакс) и уровни сложности на выбор — выбран один «средний».
- Реклама, аналитика, формы сбора данных.

## Acceptance Criteria

| # | Критерий | Как проверяется |
|---|---|---|
| AC1 | Поле 5×5 = 25 кликабельных клеток | контракт-тест + ручной осмотр |
| AC2 | Тройка по горизонтали, вертикали и обеим диагоналям дает 1 очко | `tests/rules.test.js` |
| AC3 | Линия из 4 = 2 очка, из 5 = 3 очка | `tests/rules.test.js` |
| AC4 | Клетки засчитанной линии блокируются и больше не принимают ходы | `tests/rules.test.js` |
| AC5 | Счетчик очков каждой стороны верен на протяжении всей партии | сelf-play инварианты, `tests/rules.test.js` |
| AC6 | Партия завершается (поле заполнено либо троек больше не будет) | `tests/rules.test.js`, self-play |
| AC7 | Победитель определяется по очкам, при равенстве — ничья | `tests/rules.test.js` |
| AC8 | Компьютер забирает свое очко, если может | `tests/ai.test.js` |
| AC9 | Компьютер блокирует немедленную тройку игрока | `tests/ai.test.js` |
| AC10 | Компьютер не меняет 1 свое очко на 2 очка соперника | `tests/ai.test.js` |
| AC11 | Бот всегда возвращает легальный ход; 300 партий бот-против-бота завершаются без ошибок | `tests/ai.test.js` |
| AC12 | Все `id`/классы, которые ищет `ui.js`, существуют в `index.html`; ассеты на месте | `tests/ui-contract.test.js` |
| AC13 | Страница работает по `file://` без сервера | открытие файла в браузере |

## Constraints

- Никаких рантайм-зависимостей и сборки; `node --test` — единственный инструмент проверки.
- Логика (`rules.js`, `ai.js`) не знает о DOM; `ui.js` не содержит правил игры.
- Код должен работать в браузере как classic script и в Node через `require` (UMD-обертка).
- Визуальная верификация в headless-браузере в текущей песочнице недоступна (Chrome не запускается:
  crashpad `OpenProcess` — Access denied). Компенсация: контракт-тест UI↔HTML + инварианты self-play,
  финальная визуальная проверка — за владельцем.
